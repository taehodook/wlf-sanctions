# 제재명단 통합 조회 (WLF)

OFAC · KoFIU · UN 안보리 제재명단을 매일 자동 수집해 정규화하고, 변경이력·통계와 함께 웹으로 조회합니다.
서버 없이 GitHub Actions(수집) + GitHub Pages(조회)만으로 동작합니다.

> **용도 안내** — 내부 참고용 조회 도구입니다. 실제 WLF 필터링·STR 판단은 반드시 각 기관 원본을 대조하십시오.

---

## 1. 폰으로 세팅하기 (약 10분)

브라우저에서 `github.com`에 접속해 **데스크톱 사이트 요청**을 켜면 아래 과정이 전부 가능합니다.
(GitHub 모바일 앱은 파일 생성이 제한적이라 브라우저를 권장합니다.)

| 순서 | 할 일 |
|---|---|
| 1 | **New repository** → 이름 `wlf-sanctions` → **Public** 선택 → Create |
| 2 | 저장소 화면 → **Add file → Upload files** → 이 폴더의 파일을 전부 업로드 → Commit |
| 3 | **Settings → Pages** → Source를 **GitHub Actions**로 변경 |
| 4 | **Actions** 탭 → 워크플로 활성화 동의 → **제재명단 수집** → **Run workflow** |
| 5 | 3~5분 후 `https://{계정명}.github.io/wlf-sanctions/` 접속 |

이후로는 **매일 09:00 KST에 자동 실행**됩니다. 손댈 일이 없습니다.
급할 때만 Actions 탭에서 **Run workflow**를 누르면 즉시 갱신됩니다.

> 폰 홈화면에 사이트를 추가해 두면 앱처럼 씁니다.
> 크롬 → 메뉴 → **홈 화면에 추가**.

## 2. 지금 상태

| 출처 | 상태 | 건수 | 비고 |
|---|---|---|---|
| OFAC SDN | 자동 | 19,157 | XML(별칭 포함). 원본 선언 건수와 자동 대조 |
| EU FSD | 자동 | 6,017 | 지정일 전건 보유 |
| UN 안보리 | 자동 | 1,011 | 개인 736 / 단체 275 |
| KoFIU | **자동** | 1,064 | 국가법령정보센터 고시 별표 PDF. 한글명·한국 지정일 보유 |

### KoFIU 명단은 어디서 오는가

kofiu.go.kr 게시판에는 명단이 없습니다(제도 설명 페이지뿐이고, 공지 게시판은 AJAX 전환으로
정적 접근 불가). 명단은 **금융위 고시의 별표**로 공시되며 국가법령정보센터에 올라옵니다.

```
① GET /행정규칙/{규정명}                     → 현행 admRulSeq
② GET /LSW/admRulBylInfoR.do?admRulSeq=..    → 별표 식별자(bylSeq) + 시행/고시 정보
③ GET /admRulBylContentsInfoR.do?bylSeq=..   → 원본 문서키(flSeq)
④ GET /LSW/flDownload.do?flSeq=..            → 별표 PDF
```

**①이 핵심입니다.** admRulSeq는 고시가 개정될 때마다 바뀌는데, 규정명 URL이 항상 현행 버전으로
해석되므로 개정돼도 코드를 고칠 필요가 없습니다. 현재 반영본은
**금융위원회고시 제2026-2호(시행 2026.1.22.), 1,066명**입니다.

별표 제목 끝의 "(1066명)"과 파싱 결과를 자동 대조하므로, 서식이 바뀌어 파싱이 깨지면 바로 드러납니다.

#### 평문(.txt) 경로를 쓰지 않는 이유

같은 별표를 평문으로 주는 `admRulBylTextDownLoad.do`가 있고 줄바꿈이 정돈돼 있어 편해 보이지만,
**한자를 손상시킵니다**(2026.07. 실측).

```
PDF  : HUIONE GROUP LIMITED (Chinese Traditional: 滙旺集團有限公司)
평문 : HUIONE GROUP LIMITED (CChinese Traditional: 旺集團有限公司)
```

선두 글자 누락과 라틴 문자 중복이 함께 나타나며 한자 109자 중 11자가 사라집니다.
캄보디아·중국 연계 대상(Huione 계열, 베이징 숙박소 등)의 중문 표기가 정확히 여기서 깨집니다.
나머지 1,062건은 두 경로의 파싱 결과가 완전히 동일했으므로, 원문 충실도를 택해 PDF를 씁니다.

#### 이 출처에서만 얻는 것

- **한국 지정일 658건** — `(2016. 3. 8. 지정)` 형태. OFAC에는 지정일 자체가 없어 이 값이 지정연도 통계를 메웁니다.
- **한글명** — `KOREA PUGANG TRADING CORPORATION (조선부강무역회사)`. 국내 WLF에서 한글 매칭에 직결됩니다.
- **우리 정부 독자지정분** — 영변원자력연구센터 등 미국 E.O./UN 근거 표기가 없는 항목 519건.

#### 원본 중복

고시 원문에 동일 대상이 두 번 실린 사례가 있습니다(#27=#42 완전 동일, 대소문자·하이픈만 다른 쌍 2건).
파서 오류가 아니라 원본 특성이며, 저장 시 2건이 합쳐져 1,066 → 1,064건이 됩니다. 로그에 경고로 남습니다.

#### 실패 시

네트워크·서식 문제로 자동 수집이 실패하면 `manual/` 의 수동 반입 파일(xlsx/csv/pdf)로 대체합니다.
파일명에 `kofiu` / `제한대상` / `금융거래등제한` 중 하나가 들어가야 인정합니다.
둘 다 없으면 이 출처만 건너뛰고 나머지는 정상 수집합니다.

**KoFIU가 실패해도 나머지는 정상 동작합니다.** 기존 KoFIU 데이터가 있으면 `STALE` 표시와 함께 유지되므로, 파싱이 깨졌다고 명단이 통째로 사라지지 않습니다.

## 3. 구조

```
.github/workflows/collect.yml   매일 09:00 KST cron + 수동 실행 + Pages 배포
src/sanctions_collector.py      4개 기관 수집·파싱·정규화 (클래스 구조)
src/countries.py                국적 표기 → ISO alpha2 + 한글명 정규화
src/countries.json              255개국 정본 (AML 국가위험평가에서 추출한 사본)
src/diff_engine.py              전일 대비 신규/삭제/변경 탐지 + 서킷브레이커
src/build_site.py               파이프라인 진입점 → docs/data/*.json 생성
docs/index.html                 대시보드 (빌드 불필요한 단일 HTML)
docs/manifest.json, sw.js       PWA (홈화면 추가 · 오프라인 열람)
manual/                         KoFIU 고시 파일 반입 위치 (직접 커밋)
docs/data/                      Actions가 자동 갱신 (직접 수정하지 말 것)
```

### 데이터 파일

| 파일 | 내용 | 크기 |
|---|---|---|
| `index.json` | 슬림 인덱스 `{fields, rows}` — 출처·이름·유형·uid·국적·생년월일·지정근거·지정일·국가코드 | ~2.3MB |
| `detail/{출처}/{00~23}.json` | 상세 레코드(별칭·주소·비고 포함), 키 해시로 24분할 | 샤드당 ~390KB |
| `stats.json` | 출처별·유형별·국적 Top20·지정근거 Top12·교차표·지정연도·추이 | ~2.4KB |
| `changes/{날짜}.json` | 일별 변경 상세 | 변동량에 따라 |
| `changes/index.json` | 일별 변경 요약 (최근 365일) | ~1KB |
| `meta.json` | 갱신시각·건수·출처별 수집상태·최근 변동 요약 | ~1KB |

화면은 시작할 때 `meta`·`stats`·`index`·`changes/index` 넷만 받고(약 2.3MB, 전송 시 gzip 압축),
상세와 일별 변경은 **누를 때** 해당 조각만 받습니다. 상세를 24분할한 이유는 OFAC만 1.9만 건이라
단일 파일이 8MB를 넘기 때문입니다.

> `build_site.shard_of()`와 `docs/index.html`의 `shardOf()`는 **반드시 같은 결과**를 내야 합니다.
> 한쪽만 고치면 상세 화면이 영구히 열리지 않습니다. (현재 300건 무작위 교차검증 통과)

> `docs/`의 모든 경로는 **상대경로**여야 합니다. Pages 주소가 `/{계정}/wlf-sanctions/` 하위라
> `/sw.js` 같은 절대경로는 404가 납니다.

## 4. 안전장치

**서킷브레이커** — 전체의 30%를 넘는 대량 삭제가 감지되면 데이터를 갱신하지 않고 종료(exit 2)합니다.
하루에 명단의 30%가 사라지는 일은 없습니다. 그런 결과가 나왔다면 대개 파서가 깨진 것입니다.

**소스 단위 폴백** — 특정 기관 수집이 실패하면 그 기관의 이전 데이터를 `stale` 표시로 유지합니다.

**감사증적** — 원본 파일(CSV/XML/XLSX)은 Actions Artifact로 90일간 보관됩니다. 저장소에는 커밋하지 않습니다.
Actions 실행 화면 하단 Artifacts에서 내려받을 수 있습니다.

**실패 알림** — 워크플로가 실패하면 자동으로 이슈가 생성됩니다. GitHub 앱 알림을 켜두면 폰으로 옵니다.

## 5. 알려진 한계

- **동일인 매칭 없음** — 기관 간 같은 인물을 하나로 합치지 않습니다. 출처별로 별개 레코드입니다.
  명의매칭(Entity Resolution)은 WLF 엔진의 영역이고, 여기서 섣불리 합치면 오탐 추적이 어려워집니다.
- **OFAC은 지정일이 없습니다** — CSV·XML 모두 지정일 항목이 없습니다(전량 공란).
  그래서 통계의 **지정연도 분포는 EU·KoFIU·UNSC 7,686건 한정**이며, 화면에도 모집단을 명시했습니다.
  전체 명단의 연도별 추이로 읽으면 오독입니다.
- **표는 상위 300건만 표시** — 2만 건을 한 번에 그리면 휴대폰 브라우저가 멈춥니다.
  나머지는 검색·필터로 좁혀서 봅니다(집계·통계는 전건 기준이라 영향 없음).
- **별칭 검색** — 검색은 주 이름(name)만 대상입니다. 별칭은 상세 모달에서만 보입니다.
  별칭까지 검색하려면 인덱스에 별칭 필드를 추가해야 하는데(현재 53,110개), 용량이 크게 늘어 보류했습니다.
  **이 화면은 조회·현황 파악용이지 WLF 스크리닝 엔진이 아닙니다.** 실제 명의매칭은 별칭 전량을
  적재한 엔진에서 수행해야 합니다(상세 JSON에는 별칭이 전부 들어 있습니다).
- **국적 정규화 99.9%** — 미매핑은 코소보(ISO 미등재)와 'Region: Gaza' 등 7건이며 원문을 그대로 보존합니다.
  `src/countries.json`은 AML 국가위험평가 255개국 정본의 **사본**이므로, 원본이 갱신되면 함께 갱신해야 어긋나지 않습니다.
- **기관 간 건수는 단순 합산** — 같은 인물이 OFAC·EU·UNSC에 모두 있으면 3건으로 셉니다(아래 '동일인 매칭 없음' 참조).
  총 27,249건은 '제재 대상 수'가 아니라 '등재 레코드 수'입니다.
- **KoFIU 표기 변경 추적 불가** — 고유번호가 없어 이름을 키로 씁니다. 표기가 바뀌면 `삭제 + 신규`로 잡힙니다.
  OFAC(`ent_num`)·UNSC(`DATAID`)는 고유번호가 있어 개명도 `변경`으로 추적됩니다.
- **최초 적재일은 변동에서 제외** — 수집 시작일은 전체가 `added`로 잡히지만 제재 신규지정이 아닙니다.
  화면에서 별도 표시하고 7일/30일 변동 집계에서 뺍니다.
- **cron 지연** — GitHub Actions cron은 부하에 따라 수 분~수십 분 늦게 실행될 수 있습니다(정시 보장 아님).
- **CDN 의존** — Tailwind·아이콘·폰트를 CDN에서 받습니다. CDN이 차단된 사내망에서는 표·수치는 나오지만
  레이아웃이 깨집니다. 사내 배포가 필요하면 자산을 저장소에 포함해야 합니다.
